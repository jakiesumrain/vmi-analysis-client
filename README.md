# VMI Analysis Client

Desktop companion for the [VMI Analysis server](https://github.com/jakiesumrain/vmi-analysis-gui).
It replaces the manual SSH tunnel that shared-server users start before opening
the browser with a small tray application.

```text
VMI Analysis Client
  -> SSH to the server
  -> local forward 127.0.0.1:<local port> -> 127.0.0.1:13517 on the server
  -> system browser at http://127.0.0.1:<local port>
```

The server keeps its web port on loopback; SSH is the only transport. The
client never exposes a port to the network and never runs a remote shell.

## Features (Phase 1)

- Password or key-file SSH authentication, with the OS keychain as an optional
  password/passphrase store.
- Host-key verification against a per-user `known_hosts` file: a new server key
  is recorded on first contact, and a changed key is refused.
- Automatic local port selection, or a fixed port you choose.
- Keepalive plus bounded automatic reconnect after a dropped session.
- Tray menu: show window, open the VMI page, reconnect, disconnect, quit.
- Closing the window keeps the tunnel running; quit from the tray.
- Saved connection profiles.

## Requirements

- Windows 10/11 with the WebView2 runtime (present on current Windows).
- Rust 1.90+ with the MSVC toolchain, or a Tauri 2 development environment.
- A Linux build needs the usual Tauri 2 packages (WebKitGTK, librsvg, libappindicator)
  and a Secret Service provider for the keychain. It has not been tested yet.

## Build and run

```powershell
cd src-tauri
cargo build --release
.\target\release\vmi-analysis-client.exe
```

For a development build, `cargo run` in `src-tauri` opens the same window.

The icon set is generated by `src-tauri/icons/generate-icons.py` (Pillow); the
committed icons are the output of that script.

## Use

1. Enter the server host and your SSH user.
2. Choose password or key-file authentication.
3. Leave the local port blank to let the client pick a free one.
4. Choose **Connect**. The browser opens at the forwarded loopback URL when the
   tunnel is up.
5. Sign in to VMI Analysis with your VMI account, not your SSH account.

Use **Save profile** to keep the connection settings. Passwords are only kept
when **Remember** is checked, and then only in the OS keychain.

## Files

The client writes to the platform application-config directory, for example
`%APPDATA%\com.vmi.analysis.client\` on Windows:

| File | Contents |
| --- | --- |
| `profiles.json` | Saved profiles. Never contains passwords. |
| `known_hosts` | Trusted server host keys, in OpenSSH known-hosts format. |

## Security model

- The browser only talks to `127.0.0.1`; the SSH session carries the traffic.
- Only local forwarding is used. The client does not request a shell, a PTY or
  remote forwarding, and does not run commands on the server.
- A changed host key stops the connection with an explicit error. Delete the
  `known_hosts` entry only after verifying the change with the server owner.
- Passwords and key passphrases live in the OS keychain, never in
  `profiles.json`.
- Model-provider traffic from the Agent stays server-side. This client does not
  implement an egress relay.

## Repository layout

```text
src-tauri/          Rust/Tauri application
  src/lib.rs        app shell, commands, tray
  src/ssh.rs        SSH connection, auth, host-key checks
  src/tunnel.rs     local listener, forwarding, reconnect supervisor
  src/secrets.rs    OS-keychain storage

ui/                 static window UI (no bundler)

```
